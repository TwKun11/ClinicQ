# Add Backend Search And Filter APIs

## Goal

Add backend search/filter support needed by the frontend:

- Patients: search by `fullName`, `phone`, or `email`.
- Appointments: filter by date, patient, and status.

## API Contract

- `GET /api/v1/patients?search=<term>&page=&size=&sortBy=&sortDir=`
  - `search` is optional and matches `fullName`, `phone`, or `email` case-insensitively.
- `GET /api/v1/appointments?date=YYYY-MM-DD&patientId=<id>&status=<status>&page=&size=&sortBy=&sortDir=`
  - `date` is optional and implemented as a half-open range `[dateT00:00, date+1T00:00)`.
  - `status` is optional and case-insensitive, but must map to `AppointmentStatus`.

## Senior Performance Choices

- Use Spring Data JPA `Specification` so absent filters are not emitted as `OR :param IS NULL` predicates.
- Keep filtering database-side with pageable queries; never filter in memory.
- Guard page size and sort keys in controllers.
- Add PostgreSQL trigram indexes for patient contains search.
- Add composite appointment indexes for common filtered + sorted access patterns.

## Validation

- Add focused service tests for patient search and appointment filtering.
- Run backend tests.
